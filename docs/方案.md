# DeepSeek Harness 桌面壳（dsh-ui）方案

> 状态：**历史设计稿（2026-08-14）**。正文部分描述已废弃架构（如独立浮层窗口、npx 启动、
> 顶层加载、缩放注入），当前实现以 [README.md](../README.md) / [DEVELOPMENT.md](DEVELOPMENT.md) 为准：
> 单窗口 + iframe、pnpm dlx 启动、内嵌终端等。
> 目标：把「cmd 里敲命令 → 浏览器打开 `http://127.0.0.1:3080/`」的用法，收敛成一个轻量桌面客户端：启动后自动拉起服务、内置 cmd 浮层、就绪后自动收起到按钮，主界面直接显示 Harness Web UI。

## 实施记录

- 框架：Tauri 2（tauri 2.11.5）+ WebView2，GNU 工具链（本机无 MSVC）
- 全部功能已实现并验证：ConPTY 终端、自动启动命令、就绪探测/快速失败、终端面板呼出收起、
  缩放（按钮/Ctrl±0/持久化）、Job Object 退出清理、keep-alive、单实例、auto_restart、设置页
- **架构定案**：单窗口 + iframe（Windows 第二个 WebView2 窗口合成不可用）；iframe 为
  OOPIF 独立 CDP target
- **会话记忆**：工作目录自动跟随最后会话 workspace（`~/.dsh/sessions` projectKey 有损
  编码的候选还原）；壳内打开过的会话由 harness 原生 localStorage 机制自动恢复
- **下载支持**：WebView2 DownloadStarting + PermissionRequested（自动允许多文件下载），
  会话日志导出保存到系统下载目录
- **绿色安装**：只解压（跳过运行状态检测），写 `portable.marker`，配置随程序目录走
- **便携模式**：程序目录含 `portable.marker` 时 settings.json/日志存程序同目录
- **启动可见性**：启动遮罩内嵌只读终端实时显示 console 输出（0.1.17）
- **手动停止**：终端面板「⏹」停止服务（会话树 + 按端口杀 detached）；关闭时询问
  「保持运行 / 结束服务」（0.1.16）
- **首次运行**：检测系统无 dsh → 提示「正在下载 DeepSeek Harness」+ 超时放宽 30 分钟；
  代理设置（系统代理默认 / 自定义）供下载使用（0.1.18）
- **文档**：README 含「更新记录」（与版本对应）；安装包内置 README.md（0.1.20）
- 产物：`src-tauri/target/release/bundle/nsis/dsh_shell_<版本>_x64-setup.exe`
- 用户使用见 README.md；开发/构建/调试见 DEVELOPMENT.md

## 1. 背景与现状分析

### 1.1 现状

当前用法：

1. 在 cmd 中执行命令（实际命令为 `npx @deepseek-ai/dsh web`，即 `dsh` CLI 的 web profile 别名）；
2. `npx` 按需拉取 `@deepseek-ai/dsh` 软件包；
3. `dsh web` 在前台运行，启动本地 Web 服务并阻塞（进程不退出）；
4. 手动打开浏览器访问 `http://127.0.0.1:3080/` 使用。

### 1.2 已核实的关键事实（来自本机 npx 缓存源码）

| 事实 | 说明 |
|---|---|
| 启动命令 | `npx @deepseek-ai/dsh web`（等价 `--profile web`；`bin` 只有 `dsh`，不存在名为 "DeepSeek Harness" 的命令，应是你对它的称呼） |
| 进程形态 | **前台阻塞式** Node 进程，服务在其进程内运行；杀掉进程即停止服务 |
| 端口 | 默认 `127.0.0.1:3080`（`dsh-cmdline`：`ctx.webStartup.port ?? 3080`）；可用 `--port` 覆盖；`--host 0.0.0.0` 被显式拒绝（安全考虑） |
| 首次运行 | web profile 首次使用时自动从模板初始化（无需交互），但 npx 首次下载会提示 `Ok to proceed? (y)` → 用 `npx --yes` 消除 |
| 工作目录 | **启动命令所在目录 = 默认 workspace 根目录** → 壳程序必须可配置工作目录 |
| DSH_HOME | `~/.dsh`（本机已存在 `profiles/web`、`settings.yaml` 等，用户已使用过） |
| 就绪判定 | 以 HTTP GET `http://127.0.0.1:3080/` 返回 200 为准（比解析终端文本可靠） |

### 1.3 环境约束

- Node v24.11.0、npm 11.6.1 ✅
- **无 Rust 工具链**（Tauri 需要，一次性安装 rustup）
- Windows 10/11，系统自带 WebView2（Edge 运行时）✅
- 纯本地回环服务，无远程网络暴露问题

## 2. 技术选型

### 2.1 候选对比

| 方案 | 体积 | 新增工具链 | 缩放能力 | 结论 |
|---|---|---|---|---|
| **Tauri 2（推荐）** | 安装包 ~10MB | Rust（rustup 一次性安装） | WebView2 zoom factor 原生支持（tauri PR #9378 已合入 2.x），文字清晰无损 | ✅ 轻量、贴合需求 |
| Electron | ~90MB+ | 无（纯 npm） | `webContents.setZoomFactor` 一等公民 | 备选；重、内存占用高 |
| pywebview | 小 | Python | 需走 WebView2 COM，较绕 | 不推荐 |
| .NET WPF + WebView2 | 中 | .NET SDK | `CoreWebView2.ZoomFactor` 原生 | 可行，但非 JS 技术栈，与 dsh 生态割裂 |

### 2.2 推荐：Tauri 2

理由：

1. **轻量**：打包后数 MB～十几 MB，运行时复用系统 WebView2；
2. **缩放**：Tauri 2 已合入 webview zoom API（[tauri-apps/tauri#9378](https://github.com/tauri-apps/tauri/commit/58a7a552d739b77b71d61af11c53f7f2dc7a6e7e)），直接驱动 WebView2 `ZoomFactor`，等价浏览器级缩放；
3. **子窗口**：`WindowBuilder` 具备 parent API（[tauri-apps/tauri#8622](https://github.com/tauri-apps/tauri/pull/8622)），可把浮层窗口挂为主窗口的 owner 子窗口——浮层永远只盖住主窗口，不会盖到别的应用；
4. 与 dsh 同为 JS/Rust 友好生态，前端用原生 TS 即可（仅需 xterm.js 一个运行时依赖）。

**明确不采用的方案**：同一窗口内叠加多个 webview（`window.add_child`）——Windows 上存在「新 webview 不上顶」「白屏」「定位错乱」等已知 bug（[#9798](https://github.com/tauri-apps/tauri/issues/9798)、[#10011](https://github.com/tauri-apps/tauri/issues/10011)、[#10420](https://github.com/tauri-apps/tauri/issues/10420)），风险高。

### 2.3 备选：Electron

若你不想安装 Rust 工具链，则改用 Electron：
- 架构、交互、状态机设计完全不变（本文档的 UI/流程设计对两者通用）；
- 差异仅在：进程管理用 Node `child_process` + `node-pty`（或 `@lydell/node-pty`），缩放用 `webContents.setZoomFactor`，浮层用 `BrowserWindow`（`parent` + `alwaysOnTop`）。

## 3. 总体架构

```
┌───────────────────────────── Windows ─────────────────────────────┐
│                                                                   │
│  ┌── Tauri 主进程 (Rust) ──────────────────────────────────────┐  │
│  │  terminal.rs   ConPTY 管理器（portable-pty）                │  │
│  │  server.rs     就绪探测 / 生命周期状态机 / 端口检测          │  │
│  │  zoom.rs       缩放因子管理（50%–300%，持久化）              │  │
│  │  overlay.rs    浮层窗口创建、跟随主窗口同步                  │  │
│  │  job.rs        Windows Job Object（退出时杀整个进程树）      │  │
│  └──────────────────────────────────────────────────────────────┘  │
│                                                                   │
│  ┌── 主窗口（常规边框窗口）──────────────────────────────────┐   │
│  │  WebView 加载 http://127.0.0.1:3080/（就绪前显示本地启动页）│   │
│  └──────────────────────────────────────────────────────────────┘   │
│                                                                   │
│  ┌── 浮层窗口（owner 子窗口，无边框、透明、不进任务栏）────────┐   │
│  │  ▸ 展开态：cmd 终端面板（xterm.js）+ 缩放按钮 ＋ 状态条      │   │
│  │  ▸ 收起态：一个圆形「终端」按钮（绿点=服务健康）             │   │
│  └──────────────────────────────────────────────────────────────┘   │
│                                                                   │
│  cmd.exe（ConPTY）── 由壳自动喂入启动命令，全程可手动输入          │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 启动流程状态机

```
[启动] ──▶ BOOTING
           主窗口：本地启动页（"正在启动 DeepSeek Harness…"）
           浮层：终端面板展开，自动在 cmd.exe 中执行启动命令
           （同时后台探测端口：若 3080 已有服务响应 → 跳过启动，直接进入 READY）
              │  HTTP 200 就绪（500ms 轮询，默认超时 120s）
              ▼
[READY] ◀─── 主窗口导航到 http://127.0.0.1:3080/
           浮层收起 → 右下角小按钮（绿色指示灯）
              │  点击按钮
              ▼
[PANEL]  ──▶ 终端面板重新展开（可查看日志 / Ctrl+C 手动停服务 / 手动输入）
              │  服务进程退出（被 Ctrl+C、崩溃）
              ▼
[FAILED] ──▶ 按钮变红 + 通知；提供「重新启动」；可选自动重启
```

退出应用时：默认通过 Job Object 杀掉整个进程树（cmd → npx → node → 服务）；可配置为「退出后保持服务运行」。

## 4. 功能设计

### 4.1 内置 cmd 终端（核心）

- **实现**：Rust 侧 `portable-pty`（ConPTY 后端，wezterm 同款，Windows 原生支持 cmd.exe）；前端 `xterm.js` 渲染（含 ANSI 颜色、滚动、复制粘贴、Ctrl+C）。
- **会话**：启动一个交互式 `cmd.exe` 会话（模拟用户自己的 cmd），自动喂入启动命令 `npx --yes @deepseek-ai/dsh web`（可配置，回车前在终端回显命令，与真实 cmd 行为一致）。
- **交互**：终端始终可手动输入——应对任何意外交互提示（首次安装询问、pnpm 提示等）；npx 的 `Ok to proceed? (y)` 由 `--yes` 预先消除。
- **工作目录**：启动前 `cd /d <工作目录>`（默认 `%USERPROFILE%`，设置中可改，配目录选择器）——因为 **dsh 以 cwd 为默认 workspace 根**，这点必须可配。
- **就绪双通道判定**：HTTP 探测为主；同时扫描终端输出中的错误特征（`EADDRINUSE`、`error:` 等）提前给出失败提示。

### 4.2 主界面

- 就绪前：本地 splash 页（浅色/深色跟随系统，显示状态文字 + 终端按钮）。
- 就绪后：WebView 直接导航至 `http://127.0.0.1:3080/`（WebView 顶层加载，**不用 iframe**，规避 X-Frame-Options / 跨域注入限制）。
- 外部链接（非本机地址）交给系统默认浏览器打开（`tauri-plugin-opener`），DSH 页面内的新窗口请求一律走主 WebView。

### 4.3 浮层窗口与「收起为按钮」

- 独立 Tauri 子窗口：`decorations(false)` + `transparent(true)` + `skip_taskbar(true)` + `resizable(true)`，通过 `WindowBuilder::parent(主窗口)` 成为 owner 子窗口 → 永远盖在主窗口之上、且**不会浮到其他应用上方**。
- 两种形态：
  - **展开**：终端面板（建议高度 = 主窗口 55%，锚定底部居中，可拖动/缩放）+ 顶栏（标题「DeepSeek Harness 终端」、缩放按钮 −/＋/100%、收起按钮）。
  - **收起**：窗口缩成右下角一个 ~48px 圆形按钮（绿点=服务正常，红点=已停止/失败），点击重新展开；按钮上显示实时 URL `127.0.0.1:3080`。
- **跟随主窗口**：监听主窗口 `Moved / Resized / ScaleFactorChanged`（跨 DPI 缩放）事件，同步浮层位置与尺寸；主窗口最小化时浮层同步隐藏。

### 4.4 缩放功能（对应「支持系统的缩放」）

- **机制**：Tauri 2 webview zoom API → WebView2 `ZoomFactor`（浏览器同款渲染级缩放，文字/图片清晰，非 CSS 拉伸）。系统 DPI 缩放（125%/150% 屏）由 WebView2 默认处理，无需额外工作。
- **范围**：50% – 300%，步进 10%（浏览器惯例）。
- **触发方式**：
  1. 浮层顶栏按钮 −/＋/100%；
  2. 快捷键 `Ctrl+加号 / Ctrl+减号 / Ctrl+0`；
  3. `Ctrl+滚轮`（在 DSH 页面内也生效：页面加载后通过 `webview.eval` 向顶层注入 wheel/keydown 监听，经 Tauri IPC 调 zoom 命令；需在 capabilities 中为本机 `http://127.0.0.1:3080/*` 授予 IPC 权限）。
- **持久化**：缩放值存入应用配置，下次启动自动恢复。
- **兜底**：若远程页面 IPC 注入被拒（ACL 限制），退化为「浮层按钮 + 快捷键」触发，功能不减、仅少一个手势入口。

### 4.5 生命周期与健壮性

| 场景 | 行为 |
|---|---|
| 服务已在运行（端口占用） | 探测到 200 直接进入 READY，跳过启动，终端提示「检测到现有服务」 |
| 端口被非 dsh 程序占用 | dsh 启动报 `EADDRINUSE` → 终端标红，状态条给出错误提示 +「更换端口重试」入口（用 `--port` 起新端口并导航过去） |
| 服务进程中途退出 | 探测失败 → 按钮变红、气泡通知，提供「重新启动」；可配置自动重启 |
| 退出应用 | 默认杀进程树（Job Object `KILL_ON_JOB_CLOSE`，确保 cmd/npx/node 全清）；可配置「保持后台运行」 |
| 重复启动 | `tauri-plugin-single-instance`，二次启动只唤起已有实例 |
| 首次运行（npx 下载包） | 终端可见下载进度；超时默认 120s（可配置）；期间可手动干预 |
| WebView2 缺失（罕见） | 弹窗提示并引导安装（Tauri 内置 bootstrapper 下载模式） |

### 4.6 配置项（`settings.json`，壳内「设置」入口）

```jsonc
{
  "startupCommand": "npx --yes @deepseek-ai/dsh web", // 启动命令
  "workingDir": "C:\\Users\\<user>",                  // 工作目录（= dsh workspace 根）
  "port": 3080,                                       // 探测/导航端口
  "readyTimeoutSec": 120,                             // 就绪等待超时
  "zoom": 1.0,                                        // 缩放（持久化）
  "autoStart": true,                                  // 启动即自动运行服务
  "keepAliveOnExit": false,                           // 退出时是否保留服务
  "autoRestart": false,                               // 服务崩溃自动重启
  "terminalHeightRatio": 0.55                         // 终端面板展开高度占比
}
```

## 5. 项目结构（Tauri 版）

```
dsh-ui/
├─ 方案.md
├─ ui/                        # 前端（原生 TS + Vite，仅 xterm.js 一个运行时依赖）

      └─ job.rs               # Job Object 进程树管理
```

## 7. 风险与备选

| 风险 | 对策 |
|---|---|
| 需安装 Rust 工具链（~1GB，首次编译慢） | 若不可接受 → 整体切换 Electron（2.3 节），设计不变 |
| Tauri zoom API 具体方法名/版本差异 | 锁定 Tauri ≥2.1 并验证 `set_zoom`；兜底：直接调 WebView2 zoom factor 或 CSS `zoom` |
| 远程页面 IPC 注入被 ACL 拒 | 已预留兜底（4.4），不影响核心功能 |
| `--yes` 之外的意外交互提示 | 终端可手动输入 + 自动喂命令可配置，任何提示都能人工应答 |
| 浮层子窗口跨 DPI 同步抖动 | M3 阶段专项验证 `ScaleFactorChanged`；极端情况退化为「按钮固定右下角」 |
