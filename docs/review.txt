──────── Project Summary ────────

### Top Issues

1. **Silent error swallowing is endemic in the Rust backend.** Multiple subsystems discard failures and still report success to the UI: terminal writes/resizes/kills (`src-tauri/src/terminal.rs`), settings persistence (`src-tauri/src/commands.rs` changes state, then `eprintln!`s the save error and returns `Ok`), cookie setters (`src-tauri/src/auth.rs`, four HRESULTs dropped), download handler setup (`src-tauri/src/download.rs`), and serialization fallbacks (`serde_json::to_value(...).unwrap_or_default()` in `commands.rs` turns failure into `Value::Null`). The recurring impact is that the UI shows success while disks, processes, and cookies silently keep old/partial state.

2. **Check-then-act races across lock acquisitions.** `src-tauri/src/zoom.rs` reads `g.zoom` under one lock, releases it, and writes under a second lock; `src-tauri/src/server.rs` validates the generation counter in one lock scope and performs side effects in another without re-checking; `src-tauri/src/settings.rs` has all callers write the same `settings.json.tmp` with no lock or unique suffix, so concurrent saves can interleave and rename a torn file. The same pattern appears client-side in `ui/src/shell.ts` (terminal snapshot taken before live-stream listener registration drops the gap output).

3. **The app trusts URLs, origins, and schemes it should not.** `src-tauri/src/lib.rs` allows any `data:`/`about:` URL and any `http://localhost`/`127.0.0.1` port into the top frame; `ui/index.html` assigns the backend-reported URL to a shell iframe with no `sandbox` attribute; `src-tauri/src/commands.rs` `open_browser` passes an arbitrary frontend-supplied string (any scheme) to the OS opener; `src-tauri/src/download.rs` unconditionally ALLOWs multi-download permission for any origin; `src-tauri/src/auth.rs` accepts the first `Set-Cookie` in any HTTP response (including 4xx/5xx/redirect pages). Release hardening is also undermined by unconditional `devtools` in `src-tauri/Cargo.toml` and remote debugging enabled by *any* value of the env var in `lib.rs`.

4. **Settings persistence is one bad field away from total config loss, and the settings surface is duplicated everywhere.** `src-tauri/src/settings.rs` maps every parse/type error to `Settings::default()`, so one hand-edited or migrated bad field wipes the whole user configuration. The same file hand-maintains the field list in 5+ places (struct, IPC struct, `Default`, two `From` impls), `src-tauri/src/zoom.rs` stores zoom in two fields that must be kept in sync, and `ui/src/shell.ts` reconstructs the entire `Settings` object with hardcoded values (`zoom: 1.0`, `autoStart: true`) for fields the modal doesn't edit — silently discarding prior user preferences.

5. **Terminal/process lifecycle can orphan process trees or fight over a port.** `src-tauri/src/terminal.rs` attaches the JobObject *after* `cmd.exe` is spawned, so descendants launched in that window (e.g., AutoRun) escape `KILL_ON_JOB_CLOSE`; a failed `child.kill()` is invisible to the UI. `src-tauri/src/server.rs`'s keep-running branch launches a detached second instance of `startup_command` on the same port without stopping the current session or checking port ownership, and `alive()` in `terminal.rs` treats any `try_wait()` error as "dead," inviting premature teardown.

6. **Crash/poison paths in parsing and numeric handling.** `src-tauri/src/server.rs` `decode_project_key` panics with an out-of-bounds index when a workspace is a drive root (`--C--`); `src-tauri/src/zoom.rs` propagates NaN (the `clamp` only guards the min/max, not `self`); `ui/index.html` allows fractional/exponent port input (`3080.5`, `1e2`) that reaches `u16` parsing; `src-tauri/src/settings.rs` persists semantically invalid values like `port: 0` and `zoom <= 0`.

7. **Frontend failure modes leave the user stuck with no diagnostics.** `ui/index.html` has no `<noscript>`, `onerror`, or watchdog, so a module/IPC failure leaves the boot mask and spinner up forever. `ui/src/shell.ts` `applyState` only updates a subset of elements per phase and relies on `bootMask.hidden` to mask leftovers, so non-adjacent transitions (e.g., `failed` → `ready`) leave stale error/spinner state. Compounding this, `ui/src/styles.css` disables `user-select` on boot/error text so users can't even copy the failure output.

8. **Release pipeline can silently ship nothing or destroy history.** `scripts/publish.ps1` only checks npm's exit code, never verifying an NSIS installer was actually produced before `Sort-Object ... | Select-Object -First 1` picks an artifact — potentially a stale one; `Copy-Item -Force` overwrites same-version historical installers despite the header claiming all versions are preserved.

### Module Hotspots

- **`src-tauri/src/`** — 35 of the 62 comments concentrate here. `server.rs`, `commands.rs`, `download.rs` (5 each), `terminal.rs`, `settings.rs`, `auth.rs` (4 each) carry the highest density, dominated by race conditions, discarded errors, and unvalidated input.
- **`ui/src/` and `ui/index.html`** — 11 comments across `shell.ts`, `ipc.ts`, `styles.css`, and `index.html`, mostly about unrecoverable UI states, duplicated state types, and settings being rewritten with hardcoded defaults.
- **`scripts/publish.ps1`** — only 3 comments but all point at artifact-verification and overwrite bugs in the release path.
- **`src-tauri/Cargo.toml` + `build.rs`** — release config (unconditional devtools), crate metadata, Windows crate-generation mismatch, and a duplicated icon source of truth.

### Cross-Cutting Concerns

- **Discarded `Result`/HRESULT values and `unwrap_or_default` fallbacks** — the dominant pattern. Representative: `src-tauri/src/terminal.rs`, `src-tauri/src/commands.rs`, `src-tauri/src/auth.rs`, `src-tauri/src/download.rs`, `src-tauri/src/settings.rs`.
- **State/type duplication requiring manual sync** — `Settings` field list in `src-tauri/src/settings.rs`; zoom stored twice in `src-tauri/src/zoom.rs`; `StateChangedPayload` hand-duplicated from `AppState` in `ui/src/ipc.ts`; icon list duplicated between `src-tauri/build.rs` and `tauri.conf.json`; full `Settings` reconstruction in `ui/src/shell.ts`. Every one of these compiles fine while silently drifting.
- **Unsafe cross-thread mutation and lock misuse** — check-then-act in `src-tauri/src/zoom.rs` and `src-tauri/src/server.rs`; blocking `fs::write`/`rename` while holding the global `Arc<Mutex<AppInner>>` in `commands.rs`; inaccurate `Sync` rationale in `src-tauri/src/job.rs`; the snapshot/listener race in `ui/src/shell.ts`.
- **Trusting frontend/service-provided strings at trust boundaries** — `open_browser` scheme passthrough (`commands.rs`), iframe `src` assignment without sandbox (`ui/index.html`), permissive navigation allowlist (`lib.rs`), unvalidated cookie source (`auth.rs`), permissive download permission (`download.rs`).
- **Windows-specific correctness assumptions** — `sanitize_filename` in `download.rs` misses reserved names/characters; `download_dir` falls back to the drive root when `USERPROFILE` is unset; `decode_project_key` assumes a path always has a non-drive remainder; cookie `Expires` treated as Unix epoch in `auth.rs` instead of the FILETIME epoch (~370 years off).
- **Fire-and-forget IPC calls with no rejection handling** — `ui/src/ipc.ts` wrappers and `ui/src/shell.ts` calls (`zoomStep`, restart/stop/retry, `openBrowser`) with no `.catch()`.

### Quick Wins

- **Redact the `token=` query string** before logging `web_url` in `src-tauri/src/server.rs`; log an error without the URL. One-line, removes a credential leak.
- **Add `step="1"` and integer rounding/clamping** for the port input in `ui/index.html`, and reject NaN in `src-tauri/src/zoom.rs` `clamp` — blocks corrupted settings/URLs at the cheapest layer.
- **Re-enable `user-select: text`** on `.boot-terminal` and `.error-text` in `ui/src/styles.css`, matching the existing `.panel-log`/`.modal-card` pattern so failure output is copiable.
- **Fix the system-proxy checkbox default in `ui/index.html`** to match `cfgProxy.disabled = cfgSysProxy.checked` in the runtime, and stop persisting the proxy field when system proxy is checked.
- **Attach `.catch()` handlers** to the fire-and-forget IPC calls in `ui/src/shell.ts` so backend errors surface instead of vanishing into unhandled rejections.
- **Tighten `.gitignore`** for env variants (`.env.local`, etc.), rotated logs (`*.log.*`), OS junk (`.DS_Store`, `Thumbs.db`), and editor dirs (`.idea/`, `.vscode/`).
- **Enable `isolatedModules` (or `verbatimModuleSyntax`) and add `@types/node`** to `ui/tsconfig.json` so tsc matches esbuild's per-file transpilation and `vite.config.ts` type-checks; replace `__dirname` in `ui/vite.config.ts` with an ESM-safe equivalent.
- **Validate the settings save result** in `src-tauri/src/commands.rs` (return an error/`Result` to the frontend instead of `eprintln!` + `Ok`) — small signature change, eliminates the most visible false-success case.
